# Requiro project instructions

- Keep `prd-system/requirements.md` up to date for requested feature changes before implementation. Use stable requirement IDs, plain English and short observable Done when checks. Apply the WDYM test to every new or changed sentence. Keep proposals distinct from agreed decisions and verified results. Keep implementation details in developer notes rather than product requirements.
- Keep PRD records, owners, proof and attachments outside `02-prototype/app/ui`. Access them through the API. Never embed saved documents or proof in UI source.
- Repository content and examples must be generic. Never include real employer/customer information, personal data, account identifiers, credentials or secrets. Runtime data and attachments must remain excluded from version control. Do not automatically share or publish anything.
